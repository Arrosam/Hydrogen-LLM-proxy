## Bounded contract

Implement an authenticated, per-target-service read-only remote HTTP discovery endpoint using the official MCP SDK after compatibility/source/script inspection. Support minimal initialization/capability negotiation, ping, initialized notification and `tools/list` pagination. `tools/call` must always return an explicit MCP protocol error. This is a listing interface, not a complete callable MCP server. No `list_service_tools` catalog tool, model wrapper, upstream proxy, model invocation, Gemini native support, F002 model-list filtering, authentication redesign, new credential generation, migrations, UI changes, release/version changes, push or deployment.

Read the latest saved service, bindings and policy on EVERY list request, including subsequent pages. Collect effective configurations of all model steps and Micro Agent stages (including referenced/nested services); union offered tools rather than inspecting only the first stage. Preserve whole-policy inheritance: a present Model Service step policy replaces its service mode/list; absent inherits; default is empty blacklist. Whitelisted names bypass local equivalents. Policy matching remains exact names only. Unknown upstream tools permitted by blacklist cannot be enumerated and must be disclosed as an incomplete catalog.

Expose downstream declaration names with original descriptions and real existing parameter schemas projected from saved Hydrogen tool configuration, without decrypting/exposing adapter headers, URLs, body templates, prompts or topology. Tools without the declaration contract and disabled/unbound tools are unavailable for this policy surface. Whitelisted upstream names are admin-declared, never probed: use the owner-approved permissive valid object format placeholder, with explicit description and namespaced metadata documenting unknown real schema, discovery-only/non-executable/non-validated contract. Every entry is discovery-only; custom metadata is advisory and ordinary clients may ignore it or attempt calls.

Deduplicate identical known identities/definitions across stages. `hosted_tools.name` is globally unique, but `serverTool.name` (downstream alias) is not. Concrete ambiguity: `search_a` with `{query:string}` and `search_b` with `{term:string}` can both declare `web_search` in different stages; local known `web_search` and upstream bypass `web_search` can also collide. Owner-approved disposition: explicitly fail these unions with a sanitized `catalog_conflict` protocol error, with no arbitrary override, automatic renaming or lossy schema substitution. The administrator resolves the ambiguity.

## Numbered acceptance criteria

1. **AC1 — Key/target isolation:** an existing valid enabled unexpired Key can query only an enabled target Model Service/Micro Agent in its existing service scope. Missing/invalid/disabled/expired Keys and missing/disabled/unauthorized services fail distinctly from a valid empty list; no unrelated directory or configuration leaks. Revalidate Key/scope for every HTTP request.
2. **AC2 — Official protocol/transport:** official SDK performs initialization/version/capability negotiation and suitable stateless Streamable HTTP framing. Actual official MCP client initializes, lists and paginates over loopback HTTP. MCP errors use JSON-RPC/MCP shapes, not provider inference envelopes.
3. **AC3 — Effective union:** collect each step/stage's effective configuration (whole-policy inheritance/replacement), including later stages, nested named/inline Model Services and inherited local availability. Exclude stages disabling tools and unavailable local entries. Exact-name policy behavior and whitelist bypass provenance match the dependency feature.
4. **AC4 — Truthful definitions:** enabled, bound Hydrogen tools with a downstream declaration contract expose exact downstream names, saved descriptions and real `parameters` as `inputSchema` from one source; no internal emitted-name prefix. Upstream whitelist names expose only declared availability and the approved valid object placeholder, with unknown-schema/discovery-only warnings and namespaced metadata. The catalog discloses non-enumerated upstream possibilities.
5. **AC5 — Unique identities:** identical known identity/definition is deduplicated across stages; all successful pages have unique tool names across the unchanged catalog. Ambiguous same-name different definitions/provenance return sanitized `catalog_conflict`, with no arbitrary override, automatic renaming or lossy schema replacement; the administrator resolves ambiguity (owner accepted).
6. **AC6 — Live pagination:** every page uses latest configuration; deterministic ordering/paging on unchanged configuration; bounded safe cursor parsing, scope/target binding and invalid-cursor errors. No cross-page frozen snapshot, recovery or compensation. Duplicates/omissions during config edits are explicitly owner-accepted. Inference-session snapshots remain untouched.
7. **AC7 — Empty versus error:** permitted valid service with no offered tools returns `tools: []`; malformed saved configuration, broken references, repository failures and ambiguity produce explicit sanitized protocol errors, never an empty success.
8. **AC8 — Zero execution/quota:** initialize/list/ping/notifications and attempted `tools/call` do not invoke tools, models, upstream/adapters, activate tools, add inference context, reserve/consume inference quota or write Responses/conversation/request-log state. Calls fail explicitly even for known names and malformed/unknown attempted names.
9. **AC9 — Data boundary:** entries/errors/cursors do not leak secrets, adapter URLs, internal prompts or unnecessary graph/provider topology. Synthetic fixtures plus dispatch/persistence/quota counters prove boundaries.
10. **AC10 — Review/evidence:** ISTQB risk techniques and AC mapping, full repository typecheck/test/build gates, dependency audit, actual SDK client initialization/list/pagination/rejected-call validation, independent Sol max code and test audits, fixes/retests and reviewer IDs are recorded. Local development only; preview-default version remains unchanged.
