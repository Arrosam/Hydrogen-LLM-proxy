## Scope and acceptance criteria

1. **Declaration and ownership:** bindings describe availability only. With no client tool declarations, no bound Hydrogen tool is emitted or callable. Ordinary client functions always stay client-owned, including names/aliases matching local tools.
2. **Explicit names:** declared Hydrogen tools become ordinary upstream functions using global `provider_server_side_` by default. Missing configuration uses the default; explicit empty prefix is valid. Stored names and client-facing contracts stay unchanged. Emitted names map to exact internal IDs/executors; prefix stripping never proves ownership.
3. **Conflict preflight:** residual emitted-name collisions and duplicate declared server aliases reject before any provider/adapter dispatch, with the Hydrogen-specific conflict error. No overwrite or automatic renaming.
4. **Policy location/UI:** upstream server-tool policy exists only in MODEL SERVICE, with a unified blacklist/whitelist exact-name list and searchable known names. Default empty blacklist permits extras; whitelist allows listed bypass tools only. Micro agents do not duplicate policy.
5. **Whole stage override:** service policy is base; stage defaults to inherit. Explicit stage mode/list replaces the entire policy, including an empty list, without merging. Per the owner's follow-up on 2026-10-03, each Model Service step's policy controls belong inside that step's Advanced section, with discoverable inheritance/explicit modes; service-level placement is unchanged. The separate HostedToolBinding multiselect ticket remains excluded.
6. **Decision order:** a declared server tool listed in whitelist bypasses local rewriting even when Hydrogen supplies it. Otherwise a currently offered Hydrogen match rewrites/executes locally; unmatched declarations pass unchanged when policy permits or reject the entire request locally with native tool-not-found semantics. Ordinary functions are unaffected. Absence of server declarations is valid. Unsupported raw cross-protocol declarations reject explicitly. No upstream discovery or failover redesign.
7. **Session snapshots:** discover and document stateless and stateful entrypoints. Where session identity exists, retain original configuration, executors/name map and policy across edits, history and resume; only new sessions observe changes. Stateless requests cannot be correlated and this limitation is reported honestly. No general legacy-client layer.
8. **Protocol coherence:** tool_choice, streaming/non-streaming, multi-turn, call IDs, downstream names, history and resume use the same explicit map. Final effective tools/tool_choice (including extras) undergo preflight, so request overlays cannot bypass policy. Other errors use native provider envelopes. Blocked requests perform zero upstream dispatch.
9. **Endpoint boundaries:** exercise existing top-level Responses/Anthropic loops and nested HostedToolService; explain current capability differences. Do not add a whole missing endpoint capability silently.
10. **Preview isolation:** future releases default preview; stable requires explicit release designation. Local conventions and applicable GitHub prerelease/container workflow paths must preserve channel. Main/preview/version-tag defaults cannot update stable/latest. Existing v2.2.3 classification/version remains unchanged; no release is performed.
11. **Quality gates and review:** use committed lockfile, applicable full `typecheck`, server/web tests, build and diff check; retain baseline failures. Independent review checks correctness, regressions, trust/data boundaries and test omissions, with findings resolved or explicit blockers.
12. **Real interface acceptance:** on a disposable local instance with fake providers/tools, validate UI save, input validation, persistence after reload, error recovery and visible rendering. Inspect screenshots plus functional observations/request counters. Record any environment restrictions explicitly.

## Compatibility, trust and data boundaries

This intentionally changes tool exposure for clients that relied on undeclared bound tools; the owner will communicate migration. Preserve ordinary client functions and existing downstream protocol contracts. Do not infer execution ownership from names, prefixes or model arguments. Existing operator role/scope, quota, cancellation, SSRF and adapter safeguards remain. Use synthetic credentials, fake request counters and temporary SQLite databases; no paid inference, external adapter writes, production secrets or production security settings. Upstream receives only declared/allowed effective tools and the existing request data. Existing Responses/conversation/log retention is preserved; snapshots are local session metadata subject to existing session deletion. `store:false` is not a zero-persistence claim.

Rollback: revert feature commits on this isolated branch; preserve existing release tags, configuration data and unrelated checkouts. No database destructive migration is authorized. No push, publish, merge, deployment or release command is authorized.

## Risk-based test plan

Equivalence partitions: no declarations, ordinary functions, matched/unmatched raw server tools, same/cross protocol, inherited/explicit policy, missing/empty/nonempty prefix. Boundaries: empty lists/prefix, duplicate aliases, exact-name differences, zero dispatch/calls, malformed settings. Decision table: blacklist/whitelist × listed/unlisted × local match/no match × function/server declaration. State transitions: new session → settings edit → old session continuation/resume → new session; streaming/paused call → resumed call, preserving IDs/maps. Fakes count all provider/adapter requests and avoid inference/side effects.
