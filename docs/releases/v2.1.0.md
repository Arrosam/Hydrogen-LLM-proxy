# Hydrogen v2.1.0

这是一个功能与稳定性版本：新增按服务 / Agent 的 URL 附件总预算、把 V8 堆上限与容器内存对齐，并修复了启用思考格式后流式响应可能丢失正文的问题。

## 新增

- **URL 附件总预算（`maxAttachmentBytes`）**：Model Service 与 Micro Agent 现在可以限制单次请求内联的 URL 附件总字节数，控制台的服务编辑器已提供该选项（Agent 未设置时由阶段继承）。`0` 或留空 = 不限制——代理默认不设自己的限制，只做中继；超过预算的请求会明确报错，而不是静默截断或把内存拖垮。

## 修复

- **思考格式 + 流式：未闭合的思考块不再吞掉正文**。此前若上游把思考内联在正文里（` think…` 这类模板），而该块没有闭合（被输出上限截断，或模型漏写闭合标签），流式路径会把整段内容重新归类为 reasoning，随后被判成「只有思考、没有答案」，代理发出错误帧并中止流——客户端就表现为「思考块输出完、正文没有」，且非流式（200，正文正常）与流式行为不一致。现在流式扫描器会先把候选思考块整体缓存，只有确认闭合才作为思考回放（分片回放，仍呈现为流式）；流在闭合前结束则整段按正文送出，与缓冲路径完全一致。只影响内联 ` think` 标签的模型；使用结构化 reasoning 字段的上游仍逐 token 实时流。
- **图片缓存淘汰不再因 SQLite 变量上限中断**：单次请求可能携带超过单条 SQL 变量上限的图片数量，旧的 `NOT IN` 会抛 `too many SQL variables` 使整批写入失败，连带整批缓存失效。改为在 JS 侧跳过受保护行 + keyset 游标，仍然保证每轮前进。
- **后台任务故障不再拖垮进程**：Responses 的定时清理与流式 relay 的收尾记账等未被 await 的 Promise 现在都有兜底，磁盘写满之类的错误只影响该请求，而不是变成未处理拒绝让整个进程退出。

## 内存与性能

- **堆上限与容器对齐**（`util/heap.ts`）：Node 按宿主机内存推导堆上限，在容器里可能过大（直到被内核 OOM Kill），或在托管环境里被遗留的固定值压得过小。启动时读取 cgroup 限额并以之设置 `--max-old-space-size`，父进程转为信号转发。`NODE_HEAP_PERCENT`（默认 100）可为堆外内存留出余量，`HYDROGEN_HEAP_AUTOSIZE=0` 可关闭。
- **Micro Agent 只保留最后一个阶段的上游请求体**：此前每个阶段都留一份完整 wire body（图片请求即每阶段一份 base64 拷贝），现在只保留最后一阶段供日志使用。
- **OCR 预分批**：一次 OCR 调用最多 32 张图 / 8 MiB，峰值从「整个请求」降到「一个批次」，也更贴合提供商自己的单请求图片上限；结果按批次落回对应图片。
- **更早释放**：非流式路径渲染出的上游请求体在发送前先转成有界日志字符串并释放引用，不再跨越整个响应发送期间存活。

## 兼容性

- 无数据库变更，可直接在 2.0.1 之上替换镜像。
- `maxAttachmentBytes` 为可选字段，既有服务 / Agent 定义不受影响。
- 堆自动调整默认开启，唯一的行为变化是进程实际使用的 `--max-old-space-size` 取值。
