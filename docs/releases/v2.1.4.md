# Hydrogen v2.1.4

功能版本：**服务端工具往返**。绑定了工具的服务，现在可以把"调用 + 结果"这一整轮交还给客户端，而不只是模型的最终回答 —— 这是 Anthropic 服务端工具（`web_search_20250305` 等）与 Responses API 的必要能力。Hydrogen 不实现任何具体工具：它只提供一个契约窗口，由你决定工具以什么块类型、从适配器 JSON 的哪里取条目。

## 新功能

- **工具可声明服务端工具契约**（服务器工具编辑器 →「服务端工具往返」）。三个字段：`name`（客户端声明时使用的名称）、`resultType`（返回给客户端的结果块类型，默认 `web_search_result`）、`resultPath`（条目数组在适配器 JSON 中的 JSON Pointer，留空表示适配器直接返回数组）。**不填契约的工具行为完全不变**：模型照样用它，客户端只看到最终回答。

- **适配器决定返回什么，Hydrogen 不做字段映射。** `resultPath` 选出的数组被原样放进客户端协议要求的结果块里 —— 字段名、条数、是否带摘要都归你的适配器。代理代码里没有任何工具专用词汇，换任何适配器都不用改代理。

- **一次请求里的每一轮工具往返都会返回**，不只是最后一轮。客户端因此能看到完整的 `server_tool_use` → 结果 → 最终答案链路。

- **流式下按 content block 逐块发出**，与非流式形状一致；每个块都正确开合，严格客户端不会丢弃未闭合的块。

- **客户端回传的往返块会被保留**（`server_tool_use` / `web_search_tool_result` 等），续接不会丢内容或降级成纯文本。

## 设计要点

- **暴露范围不变**：仍由原有的按 Model Service / Micro Agent 绑定决定，只有绑定了该工具的服务才有这个能力。
- **声明名与工具名可以不同**：客户端声明 `web_search`、你绑定 `search` 也成立，按契约里的 `name` 匹配。
- **失败不伪装**：`resultPath` 选不到数组时，结果块带 `is_error: true` 且内容为空 —— 这是"适配器出错"，不会被伪装成"搜索无结果"。
- **丢弃幽灵调用**：模型偶尔会调用**声明名**而不是真实工具名，这种调用不会到达任何适配器（声明里没有参数，重写后的真实工具才有）。它被丢弃，而不是让客户端去执行一个本该服务端执行的工具。

## 升级与兼容性

- 无数据库变更：`serverTool` 是工具定义中新增的可选字段，旧工具不受影响，直接在 2.1.3 之上替换镜像即可。
- 未配置契约的服务与客户端完全不受影响；不带服务端工具声明的请求走原路径。
- 要让 Anthropic 客户端（如声明 `web_search_20250305` 的客户端）收到往返，需要：给工具填上契约 + 让适配器把结果整理成条目数组。
