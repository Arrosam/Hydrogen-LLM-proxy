# Hydrogen v2.2.1

This patch release adds **reference-image generation and image editing** to image Model Services, alongside the existing text-to-image endpoint.

## Image references and editing

- Adds **`POST /v1/images/edits`** using the same `image` Model Service category and mappings as `/v1/images/generations`.
- Supports multipart `image` uploads, repeated `image[]` reference files, and an optional `mask`. Image and mask file parts, filenames, content types, and the multipart boundary are preserved.
- Supports native JSON URL/data-URL references when the upstream provider accepts JSON on `/images/edits`. Hydrogen does not download references or convert between JSON and multipart formats.
- Preserves provider-specific JSON reference fields sent to `/images/generations`; requests are not automatically redirected to a different upstream operation.
- Reuses mapped upstream model names, per-step overrides, token authentication and service scope, retry/fallback, timeouts/cancellation, provider egress proxies, and JSON keepalive behavior.
- Routes edits through enabled OpenAI-compatible alternate endpoints even when a provider's primary endpoint is Anthropic.
- Adds fuzzy URL normalization for `/images/edits` and `/images/edit`, and updates English/Chinese service-editor labels and API documentation.

## Multipart correctness

- Recognizes complete delimiter lines rather than boundary-like substrings inside binary images.
- Matches literal form-field names and distinguishes uploads using either `filename` or `filename*` from text fields.
- Rewrites every duplicate text `model` field so upstream parsing cannot bypass the configured model mapping.
- Inserts override fields before the real closing delimiter, preserving multipart epilogues.
- Rebuilds each retry/fallback form from the original upload, preventing duplicated overrides or leakage of the previous step's parameters.
- Logs multipart byte counts instead of uploaded image/mask bytes; successful base64 image results are not retained as log payloads. Transcription text logging remains intact.

## Usage and compatibility

```bash
curl http://localhost:8080/v1/images/edits \
  -H "Authorization: Bearer sk-hproxy-..." \
  -F 'model=image-service' \
  -F 'prompt=Add a blue hat to the cat in the reference image' \
  -F 'image=@reference.png'
```

Add `-F 'mask=@mask.png'` for masked editing. For multiple references, repeat `image[]` file fields when the upstream model supports them.

- No database migration, new provider type, or new service category is required.
- Existing text-to-image requests and service definitions remain compatible.
- The upstream must support the requested operation, reference count, mask, and body format. Hydrogen forwards the provider's protocol rather than emulating editing capabilities.
- Image Model Services remain non-chat passthrough services and cannot run inside Micro Agents.
- Runtime requirements remain Node 22.12+; the container uses Node 22.
