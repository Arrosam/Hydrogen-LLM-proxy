# Hydrogen v2.1.3

补丁版本，只改一件事：**思考（thinking / reasoning）的识别与分离**。Hydrogen 是决定"模型的思考到哪里结束"的那一层，这一层此前有四种出错方式，每一种都会让客户端把推理显示成正文 —— 或者干脆没有正文。全部修掉，并新增"按服务声明思考边界"作为非标签形状模型的确定性出路。

## 修复

- **思考块不再在"被引用的"闭合标签处提前结束。** 之前取思考区域里第一个闭合标签形状的 token，包括模型推理里正在**谈论**这些标签时写下的那一个（写在行内代码里、代码围栏里，或两侧被反引号包住）。一旦切早，剩下的推理连同后面的答案都会被当作正文发出——客户端于是把推理渲染成输出，看起来就是"思考溢出到回答"。现在这类引用会被跳过，由后面真正的那一个结束；如果整段里只有引用、没有真正的结束标签，则整块按正文处理（与"未闭合的块算正文"同一条安全方向，宁可丢思考块，不丢答案）。
- **标签名字按词干识别，闭合不再要求与开标签同名。** 之前只认三个固定拼写，且只能用开标签的名字闭合。于是：模板把词干包起来的写法（`<chain_of_thought>`、`<thinking_process>`、`<deep_think>`）、以及"开一个拼写、闭另一个拼写"的模型，整块都识别不出来，原始标签会作为答案发给客户端。现在 `think` / `reason` / `thought` 的任意包裹形态都认，标签内部的空白与零宽字符（模型偶尔会在 token 里带 U+200B）都被容忍，任意同义名都能闭合。`analysis` / `result` / `div` 这类**结构化答案包装标签故意不匹配**——在真正答案开头的标签不是思考。
- **流式与缓冲不再对同一响应给出不同结果。** 流式扫描此前按缓冲区的原始长度决定放弃，于是"缩进较宽的模板"、或"带空格的标签被 delta 切开"这两种情况在流式下根本不扫描、非流式却扫描成功——同一个上游、同一段内容，客户端是否要求流式会得到不同结果。现在两条路径共用同一套匹配器，"只有空白"永不结束扫描。
- **传入形态覆盖补齐（含一条会吞掉正文的）。** 思考可能来自四个字段名（`reasoning`、`reasoning_content`、`reasoning_text`，以及 Ollama 原生 API 的 `thinking`）、`reasoning_details` 的多种形状、或 content 数组形式的 part。其中**流式响应里 content 为数组的 delta 此前被整段丢弃**——这在下游就表现为"只有思考、没有输出"。现在全部可读，且取值规则改为**第一个非空字段**（此前 `reasoning: ""` 会遮蔽后面有值的 `reasoning_content`，思考被静默丢弃）；请求日志视图读同一组字段，不再出现"日志里看不到 thinking"或读数与解析器不一致。

## 新功能

- **按服务声明思考边界**（服务编辑器 →「思考开始标记 / 思考结束标记」）。用于**思考不是标签形状**的模型——这类标记任何"按名字猜"的规则都覆盖不到，例如 GPT-OSS 的 harmony channel：`<|channel|>analysis<|message|>` 开始、`<|channel|>final<|message|>` 结束。声明后按字面量匹配、不再做形状猜测；**声明本身即启用扫描**（即使思考格式仍是"原样透传"）；结束标记即答案起点，并从答案中移除；两半都填才会保存（半对等于没配，却看起来像配了）。

## 升级与兼容性

- 无数据库变更：定义中新增的是可选字段，旧定义不受影响，直接在 2.1.2 之上替换镜像即可。
- 行为变化（预期内）：此前"能扫但不完全"的服务现在会正确分离思考——带空格的标签、混用拼写的标签、`reasoning_details`、`thinking` 字段、流式数组 content。如果某个客户端此前恰好依赖"标签原样出现在正文里"，它会开始收到 reasoning 字段 / thinking 块；这正是本次修复的目标，若确实需要原样透传，把该服务的思考格式设为「原样（透传）」即可。
- 未声明思考边界的服务完全不受新功能影响。
