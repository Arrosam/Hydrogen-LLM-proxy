# Hydrogen v2.1.6

功能补强：**服务端工具循环的续跑（`pause_turn`）**。此前工具循环到达轮次上限时直接返回错误，调用次数一多就很难看；现在改为按 Anthropic 协议暂停并允许客户端续跑。

## 新功能

- **轮次上限改为 `pause_turn` 而不是错误。** 循环到达上限时返回 `stop_reason: "pause_turn"`，并保留模型这一轮已经说出的内容。客户端把该响应**原样发回**即可继续，直到循环自然结束。

- **暂停发生在调用发出之前。** 预算在发送任何调用之前判定，所以暂停时没有任何“执行到一半”的工具，续跑时整批重放是干净的。

- **暂停时不发送结果块。** 响应里是 `server_tool_use` 之后**没有结果**——这正是协议里“此调用待执行”的形态。为它编造一个结果会报告一次并未发生的失败。

- **调用预算与轮次上限分开处理。** `maxCalls` 按**每个调用**判定：超出的调用以 `tool_call_limit` 错误返回给模型，模型当轮即可调整；只有**轮次上限**才结束整个回合。

- **Responses 侧对应形态。** 该协议没有 `pause_turn` 状态，对应为 `status: "incomplete"` 且 `incomplete_details.reason = "pause_turn"`；流式与非流式一致。

## 实现要点

- 续跑的识别不依赖额外状态：**“最后一条 assistant 轮里有声明过、但没有结果的调用”本身就是续跑信号**，所以用 `previous_response_id` 或直接回传历史都能继续。
- 只有**声明过**的服务端调用才被代理认领。与绑定工具同名的**客户端**工具仍然由客户端执行——即使两者名字相同也不会被代理重跑。
- 客户端撞名校验按工具契约里声明的名字判定：声明名不冲突即放行，其余同名仍按 400 拒绝。

## 升级与兼容性

- 无数据库变更。
- **行为变化（预期内）**：此前到达轮次上限会收到错误的服务，现在会收到 `pause_turn`。若客户端不认识该 stop reason，请让它把响应原样发回；不续跑则与之前一样“没有最终答案”，但不会丢失已产出的内容。
- 调用预算超限的行为**不变**（仍按调用返回错误）。
- 未配置服务端工具契约的服务完全不受影响。
