# Hydrogen v2.1.2

补丁版本：进一步降低带图（尤其带 OCR 预处理的）请求的瞬时内存，并修复堆自适应在「没有内存限额的容器」里完全不生效的问题。

> 说明：本版本合并了原计划单独发布的 2.1.1 内容；2.1.1 不再单独发布（tag 已移除），其改动全部包含在本版本中。

## 修复

- **容器没有显式内存限额时，Node 的堆上限不再停留在默认值。** 堆自适应原先只读 cgroup 限额（/sys/fs/cgroup/memory.max）；但 docker run / compose 不写 mem_limit 时该值是 max，于是没有任何数字可读，Node 继续沿用自己的默认上限——在约 4 GB 的机器上是 2006 MB。结果就是「分配了 4 GB，内存却在 2 GB 处 OOM 崩溃」。现在：读不到 cgroup 限额、但检测到自己运行在容器内（/.dockerenv 或 /proc/1/cgroup）时，回退使用宿主机总内存（os.totalmem()）作为上限，仍由 NODE_HEAP_PERCENT（默认 100）缩放；宿主机上的裸进程（本地开发、非容器）不受影响。启动日志会打印一行 hydrogen: <container|host> memory <N> MiB -> node --max-old-space-size=<M>，便于确认生效。
- 新增回归测试：容器内无 cgroup 限额时按宿主内存重设堆；非容器环境不重设；容器探测本身的用例。

## 优化

- **图片哈希不再把整张图解码成一个 Buffer。** OCR 缓存的内容寻址以前会把每张图的 base64 一次性解码（一张 25 MB 的图约等于 18 MB 的 Buffer），多个并发叠加起来很可观。现在按 256 KiB、4 字符对齐的分片增量喂给 SHA-256：解码出的字节与整串解码逐字节相同，因此哈希值不变、已有缓存条目继续命中，只是不再需要一整份原始字节常驻。新增回归测试校验「大图分片哈希 == 整串解码哈希」。

## 一并包含（自 v2.1.0 起）

- 按 Model Service / Micro Agent 的 URL 附件总预算（maxAttachmentBytes，控制台可配，0/留空 = 不限制）；
- OCR 预处理分批（32 张 / 8 MiB 一次调用），峰值只与单批相关；
- Micro Agent 每阶段不再保留整份渲染后的 wire body；
- 图片缓存淘汰改用 keyset 游标，不再因 SQLite 变量上限中断整批写入；
- 后台异步路径加固：prune 定时器、Responses 任务 promise 与流式 relay 的记账失败不再导致进程退出。

## 升级与兼容性

- 无数据库变更，可直接在 2.1.0 之上替换镜像。
- OCR 缓存键（哈希前像）未变，已有缓存条目继续命中。
- 共享宿主机上建议把 NODE_HEAP_PERCENT 设为 75-80，为堆外的 Buffer、SQLite 以及同机其它容器留出余量。
