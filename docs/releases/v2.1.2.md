# Hydrogen v2.1.2

补丁版本：修复容器堆自适应在「没有内存限额的容器」里完全不生效的问题。

## 修复

- **容器没有显式内存限额时，Node 的堆上限不再停留在默认值。** v2.1.1 的堆自适应只读 cgroup 限额（/sys/fs/cgroup/memory.max）；但 docker run / compose 不写 mem_limit 时该值是 max，于是没有任何数字可读，Node 继续沿用自己的默认上限——在约 4 GB 的机器上是 **2006 MB**。结果就是「分配了 4 GB，进程仍在 2 GB 处 OOM 崩溃」。现在：读不到 cgroup 限额、但检测到自己运行在容器内（/.dockerenv 或 /proc/1/cgroup）时，回退用宿主机总内存（os.totalmem()）作为上限，仍由 NODE_HEAP_PERCENT（默认 100）缩放；宿主机上的裸进程（本地开发、非容器）不受影响。
- 新增回归测试：容器内无 cgroup 限额时按宿主内存重设堆；非容器环境不重设；容器探测本身的用例。

## 升级与兼容性

- 无数据库变更，可直接在 2.1.1 之上替换镜像。
- 共享宿主机上建议把 NODE_HEAP_PERCENT 设为 75-80，为堆外的 Buffer、SQLite 以及同机其它容器留出余量。
- 启动日志会打印一行 hydrogen: <container|host> memory <N> MiB -> node --max-old-space-size=<M>，便于确认生效。
