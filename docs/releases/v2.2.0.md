# Hydrogen v2.2.0

This minor release adds **Jev / Laya semantic classification** and replaces implicit thinking-text detection with **explicit per-upstream decoding**, including safer continuation handling.

> **Read the migration section before upgrading.** Services that relied on implicit thinking-tag scanning or service-wide `thinkingDelimiters` need configuration changes. No database schema migration is required.

## Semantic classification: Jev / Laya

- New `classification` Model Service category with the native **`POST /v1/systemone`** protocol: `state` plus typed **Choice**, **Score**, and **Noul** questions, returning keyed structured answers rather than generated chat text.
- Reuses the existing mapped-model routing, ordered step chain, per-step extra parameters, retry/backoff/fallback, timeout/cancellation, client-token service scope, and quota checks.
- Preserves native probabilities, confidence, model identity, routing/truncation metadata, and provider-specific JSON fields. Input/output usage is recorded against Hydrogen token quotas; typed answers are retained in size-bounded request logs.
- Supports **`POST /v1/systemone/batch`** as Laya's batched-state extension, preserving result order and charging aggregate `total_usage` once. This is not a promised Jev endpoint: Hydrogen does not emulate batches for an unsupported provider.
- Adds native classification setup and editable request examples to the service editor and Model Bench, with English/Chinese guidance. Classification remains outside Micro Agent chat stages and OCR pre-passes, like the other non-chat passthrough categories.
- Handles Laya's native FastAPI `detail` errors, including bounded validation messages without echoing rejected input fields. Supports Laya servers with or without upstream Bearer authentication.

Setup and examples: [semantic classification guide](https://github.com/Arrosam/Hydrogen-LLM-proxy/blob/v2.2.0/docs/semantic-classification.md).

## Explicit thinking decoding and presentation

- Adds **per-step `thinkingParser`** configuration: `off`, exact initial `think_tags`, or explicit `custom` literal delimiters. The editor exposes an **Upstream thinking decoder** beside each model/provider.
- Separates upstream decoding from service-wide `thinkingFormat`. Presentation now shapes already-decoded reasoning; choosing `none`, `reasoning`, or another output format does not automatically scan arbitrary answer text.
- Uses one incremental state machine for buffered and streamed decoding, before answer validation and canonical history capture. Native structured reasoning remains authoritative.
- Built-in `<think>` handling protects quoted/code examples with bounded lookahead. Custom delimiters remain literal. Partial, interrupted, malformed, or excessively ambiguous boundaries fail explicitly rather than relabeling uncertain reasoning as an answer. Token-limit and other non-clean stop reasons, or EOF without a terminal event, cannot promote an unresolved quoted tail into answer text.
- Adds `unterminated: "error" | "reasoning"`; the default is an explicit error. The alternate retains an unclosed block as reasoning, never as answer text. Reasoning-only output still fails answer validation.
- Omits raw token logprobs while inline decoding is active, because their alignment no longer matches the transformed response and they may contain hidden reasoning tokens.
- Model Bench now reports malformed or incomplete decoded streams as failures rather than successful terminal responses.

## Continuation safety

- Preserves canonical reasoning, signatures, redacted blocks, and replay metadata independently of client presentation.
- Rejects lossy **`none` / `think_tags`** presentation for stateless responses containing replay-required reasoning, with a clear configuration error instead of silently exposing hidden thinking or returning an unusable continuation. Streaming failures terminate through the protocol error path, not a successful completion event.
- Stored Responses/Conversations and hosted tool loops retain canonical originals, so client-facing presentation can be lossy without discarding retained continuation state.
- `store: false` without a durable conversation does not provide retained continuation and therefore receives the same replay-safety check. A supplied conversation can retain history independently of response storage.

Configuration and migration: [thinking formats guide](https://github.com/Arrosam/Hydrogen-LLM-proxy/blob/v2.2.0/docs/thinking-formats.md).

## Upgrade and compatibility

1. Back up the existing data directory and configuration before upgrading. Runtime requirements remain **Node 22.12+**; the container uses Node 22.
2. If a model emits inline `<think>…</think>` blocks, add `thinkingParser: {"mode":"think_tags"}` to **that upstream step**. Output formats no longer enable implicit detection.
3. Move old service/agent-level `thinkingDelimiters` into the appropriate step's `thinkingParser: {"mode":"custom","delimiters":{"open":"…","close":"…"}}`, then explicitly remove the legacy shared setting. Old definitions are rejected with migration guidance, not silently ignored. Do not assign one grammar blindly across heterogeneous fallback models.
4. For stateless conversations with replay-required reasoning, use `original`, `reasoning`, or `reasoning_content`, or move to stored Responses/Conversations. `none` is a presentation policy, not an arbitrary-text confidentiality filter, and does not reduce provider billing. The pre-existing generation-level `thinking: "disabled"` behavior still removes reasoning before buffered canonical replay checks if an upstream ignores that setting; use a compliant upstream rather than relying on that ignored control to preserve signed continuation.
5. Configure Jev/Laya providers through a JSON/Bearer OpenAI endpoint type with a base URL **including `/v1`**, then select the classification service category. This routing convention does not mean those providers support chat completions. Map Jev to an available ID such as `jev-latest`; pin Laya with `english`, `multilingual`, or `typed-decisions` as appropriate.
6. Use a Laya-only chain for `/v1/systemone/batch` unless every fallback supports the batch route. Confidence formulas and option/context limits differ between Jev and Laya; a threshold is not portable merely because the JSON format matches.
7. No new database migration, provider enum, or dependency changes are introduced. Existing mappings, client tokens, and service retry/fallback policies remain in place.

## 升级提示（中文）

- 新增 `classification`（语义分类）模型服务，使用 Jev / Laya 原生 `/v1/systemone`；Laya 批处理使用 `/v1/systemone/batch`，不为 Jev 模拟批处理。
- 思考输出格式与上游解码分离：`thinkingFormat` 不再自动扫描正文。对内联 `<think>` 输出，请在对应上游步骤显式设置 `thinkingParser`。
- 旧服务/代理级 `thinkingDelimiters` 必须迁移至各上游步骤的 `thinkingParser.mode = "custom"`；迁移前旧定义会明确拒绝，而非默默丢弃配置。
- 需要原始 reasoning/signature 回放的无状态续接，不允许 `none` / `think_tags` 有损输出。请改用原生思考格式，或使用保留 canonical 历史的 Responses/Conversations。
- 无新增数据库迁移。升级前备份实例数据，先核对受影响的服务配置。
