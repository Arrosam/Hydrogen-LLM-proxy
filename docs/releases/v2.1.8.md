# Hydrogen v2.1.8

本次版本集中修复全仓审查发现的安全、配额、协议转换和流式交付问题，并保留 v2.1.7 的线性 SSE framing 与大工具参数保护。

> **升级前请阅读兼容性说明。** 虽然版本号为补丁版本，本次安全加固会收紧旧备份、旧会话、视频任务 ID、附件预算和管理员权限的行为。

## 安全与控制完整性

- 首次启动不再使用公开默认密码；`ADMIN_PASSWORD` 留空时生成随机临时密码并仅写入本地启动日志。服务器强制限制首次登录会话：改密前只能完成密码设置、读取自身资料或退出登录。
- 修改密码立即撤销旧会话；退出登录撤销该账户的全部会话。仪表板运行时配置的 Session TTL 现在应用于新会话和 cookie。
- 代理出口也校验目标地址，禁止借代理绕过本地 SSRF 检查；提供商连接测试中的代理选择仅限管理员。补充 IPv6 NAT64/6to4 等转换地址分类。
- 配额在异步执行前预留，防止并发请求同时消费最后一份额度；失败、空答案和重试已消费的 token 仍纳入计量。
- 提供商额外请求头不再泄露给 manager；使用已保存凭据的 Bench、服务测试和 OCR 测试仅限管理员。`/v1/models` 按客户端密钥服务范围过滤。
- 备份格式升级为 v2：口令封装的完整性摘要认证所有表数据和恢复相关元数据。恢复必须包含启用的管理员，恢复准备阶段持有请求准入锁，旧会话撤销与恢复事务一起提交。
- 视频任务路由改为绑定创建者 API 密钥的 HMAC 签名 ID；轮询/下载同时检查视频服务类型、当前映射和端点，不能再使用客户端拼接的后缀选择供应商凭据。

## 流式与协议修复

- Anthropic、Chat Completions 和 Responses 的 SSE 错误保留供应商真实诊断；确定性拒绝不再作为通用 502 反复重发。已提交的响应通过协议错误帧结束。
- 零帧短流在尚未提交响应时返回真实 HTTP 错误，不再只产生 TCP reset。日志、计量或其他结束阶段异常不会遗留永久活动请求或 Responses 任务槽位。
- conversation 历史以内部 canonical 快照保存，不再依赖 Responses 请求项的有损重渲染；Anthropic thinking 签名、redacted block 和跨协议私有内容保留用于续接。
- 补全 content_filter、pause_turn、上下文耗尽的停止原因映射；恢复 Anthropic block_start 中携带的工具输入；Chat reasoning 回放采用第一个非空字段。
- 手动 thinking 预算严格低于客户端输出上限，不擅自增大 `max_tokens`；图片 detail、logprobs 和暂停的服务端工具调用得到保留。
- 修复带 query 的 Base URL 路径拼接、无效 `n` 校验、TTS 分片 UTF-8 解码、SSE 历史并发删除结束信号及媒体交付日志。

## 执行、资源与部署

- URL 附件默认总预算为 50 MiB；最多 32 个不同 URL 共享一次下载期限，并在读取期间检查剩余字节预算。重复引用的内联膨胀也计入总预算。
- 上游错误体读取最多 64 KiB，缓冲 JSON 成功响应最多 25 MiB；备份导出预检表大小并限制最终包大小，避免生成无法恢复的无界包。
- 嵌套 hosted-tool loop 同时遵守自身与祖先调用上限；强制 server-tool choice 正确重映射；fabricated stream 的速率预算从执行开始计时。
- OCR/ASR 在写入新缓存前刷新成功命中项；OCR 路由条件基于原始输入。canonical overrides 使用完整的类型化键清单。
- 清空日志不再同步执行 VACUUM；小时级日志清理默认最多保留 100,000 行。
- Docker 使用锁文件 `npm ci`，运行阶段改为非 root；Compose 停止宽限期为 35 秒。CI Action 固定到 commit SHA，发布镜像前执行类型检查、测试、构建和依赖审计。
- 更新已知存在安全公告的依赖；增加浏览器安全头，缩减公开密钥查询数据；删除未引用 legacy 代码，忽略本地审查脚本。

## 升级与兼容性

1. **运行环境要求 Node 22.12+。** Docker 镜像使用 Node 22。
2. **升级前保存可信实例的数据库/文件系统副本**，包括 `/data` 与 `hydrogen-secrets.json`。升级原实例后重新导出 v2 备份。旧 v1 包没有表数据认证，升级后拒绝恢复；不要把来源不可信的旧包当作经过认证的备份。
3. **现有仪表板 cookie 会失效，需要重新登录。** 历史默认临时密码会在启动时轮换；请查看启动日志。设置临时密码时仍需输入当前临时密码。
4. **旧的未签名视频任务 ID 会被拒绝。** 新任务 ID 绑定创建者；保持 `SESSION_SECRET` 稳定才能跨重启继续轮询。
5. `maxAttachmentBytes` 未设置或为 `0` 时采用 **50 MiB 默认总预算**，不再表示无限。可配置正值覆盖；URL 数量和总下载期限仍受限。
6. 配置 `maxTokens` 的 API 密钥同时只准入一个计量请求；单次请求的实际用量仍可能超过剩余额度。manager 无权再执行消耗已保存凭据的 Bench/测试接口。
7. Docker 以 UID/GID **1000:1000** 运行。旧 bind mount 若归 root 所有，部署前可能需要由管理员执行 `chown -R 1000:1000 data`。本次代码没有修改用户数据目录的权限。
8. 备份最终序列化包上限为 128 MiB；过大时明确拒绝导出，可选择不包含日志或先缩短保留期。日志默认安全行数上限为 100,000。
9. 无新增数据库 schema migration。供应商、模型、服务配置和数据目录继续原位使用；请先完成上述备份与权限准备。
