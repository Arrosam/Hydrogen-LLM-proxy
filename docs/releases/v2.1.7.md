# Hydrogen v2.1.7

本次补丁版本包含两个与请求协议和流式稳定性有关的修复：已在主线中的
**DeepSeek 原生 thinking 控制**，以及本版本新增的**大工具参数 SSE 解析性能修复**。

## 修复

- **支持 DeepSeek 原生 thinking 控制。** `/v1/chat/completions` 现在识别
  `thinking: {"type":"disabled"}`、`thinking: {"type":"enabled"}` 以及带正数
  `budget_tokens` 的启用请求。已有的 `reasoning_effort` 解析优先，原生 `thinking`
  只在没有得到既有 canonical thinking 设置时作为回退；跨协议转换继续使用统一的
  thinking 表示，不会为了推理而擅自扩大客户端的输出上限。

- **修复大工具参数导致的二次 SSE 解析。** 共享 SSE framing 层改为增量、线性的行和帧
  解析，保留 UTF-8 分片、LF/CRLF、多行 data、背压和取消语义。Chat Completions、
  Messages、Responses 的工具参数都经过统一的大小限制和完成时 JSON 校验；超过帧或
  聚合参数上限、或参数 JSON 损坏时，会返回结构化协议错误而不会进入工具执行器。
  新增的 focused regression 覆盖了多 MiB 分片参数、Responses 完成快照、字符边界、
  取消、背压和 hosted-tool dispatch 顺序，避免恢复原先接近二次复杂度的 stall。

## 升级与兼容性

- 无数据库迁移；现有 `/data`、`hydrogen-secrets.json` 和 provider 配置无需改变。
- SSE frame 与流式工具参数各有 25 MiB 上限；hosted tool 的既有 1 MiB 渲染请求限制
  保持不变。大于限制的调用现在会被明确拒绝，而不是等待无界解析。
- 生产镜像：`ghcr.io/arrosam/hydrogen-llm-proxy:v2.1.7`
